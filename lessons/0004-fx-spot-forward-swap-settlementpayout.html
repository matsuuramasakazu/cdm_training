1. 金融実務の3商品（Spot / Forward / Swap）と CDM の構造比較

まず、為替市場で最も取引量の多い「物理受渡（元本交換 / Deliverable）」型の3商品の実務上の意味と、CDM（.rosetta 一次ソース）における表現を対比しましょう。

  • FX Spot（直物為替取引 / Foreign Exchange Spot）：
    約定日（Trade Date）から市場慣行で定められた標準受渡日（Spot Date：主要通貨ペアでは通常 T+2営業日、USD/CAD等は T+1営業日）に、合意したスポットレートで2通貨の元本を実際に交換（受渡決済）する取引。
  • FX Forward（為替予約・先渡取引 / Outright Forward）：
    スポット日より先（例：1ヶ月後、6ヶ月後など）の将来の特定受渡日（Value Date）に、約定時点で合意したアウトライト・フォワードレート（スポットレート＋フォワードポイント）で2通貨の元本を交換する取引。
  • FX Swap（為替スワップ取引 / Foreign Exchange Swap）：
    同一の2通貨について、期近の受渡日（Near Leg / ニアレッグ / 期近レッグ：通常はスポット日）に一定金額を交換し、同時に期先の受渡日（Far Leg / ファーレッグ / 期先レッグ）に支払・受取方向を反転させて同額の基準通貨をフォワードレートで再交換する1本の契約。
    ※注意：期中に定期的な金利キャッシュフロー（固定金利 vs 変動金利など）を交換する「通貨スワップ（Cross-Currency Swap）」は、CDMでは金利商品（InterestRatePayout × 2 ＋ principalPayment）としてモデル化されます。期中の利払いがなく期近と期先の2回の通貨交換のみを行う「為替スワップ（FX Swap）」は SettlementPayout × 2 で表現されます。

FX Swap マッピングの3つの設計ポイント

  1. TradeLot は1個、その中の priceQuantity が2個：
    FX Swap は1回の約定（単一ロット）で2つのレッグを持つ複合商品（Composite Product）であるため、tradeLot 配列を2つに分けるのではなく、単一の TradeLot の中に priceQuantity を2要素（Near Leg 用と Far Leg 用）並べるのが正規設計です（product-template-type.rosetta:L319, ingest-fpml-confirmation-product-fxswap-func.rosetta:L87-L107）。
  2. SettlementPayout -> payerReceiver は基準通貨（underlier = perUnitOf）の支払・受取方向を表す：
    上記例では Near Leg も Far Leg も為替レートの分母（perUnitOf）は GBP なので、underlier（observable-1, observable-2）はどちらも Cash: GBP です。
    • Near Leg（2002-01-25）：payer: Party1, receiver: Party2 → Party1 が 10,000,000 GBP を支払い、対価として Party2 から 14,800,000 USD（derivedQuantity）を受け取ります。
    • Far Leg（2002-02-25）：payer: Party2, receiver: Party1 → Party2 が 10,000,000 GBP を支払い（返還し）、対価として Party1 から 15,000,000 USD（derivedQuantity、レート 1.50）を受け取ります。
  3. Near Leg / Far Leg で別々の USI / UTI が付与される場合（fx-ex26 / fx-ex29）：
    規制報告（CFTC / EMIR 等）の実務では、FX Swap の Near Leg と Far Leg に別々の取引識別子（USI/UTI）が採番されるケースがあります。CDMでは Trade -> tradeIdentifier (1..*) が複数カーディナリティを持つため、1つの Trade の中に2つの UniqueTransactionIdentifier を並べて格納できます（下のインタラクティブ探索 C5 参照）。

C1: SettlementPayout（extends PayoutBase）の構造と制約

SettlementPayout（product-template-type.rosetta:L406-L460）は、親型 PayoutBase（product-common-settlement-type.rosetta:L65-L79）を継承し、原資産の受渡または差金決済を表現します。

  • PayoutBase から継承する4属性：
    1. payerReceiver PayerReceiver (1..1)：underlier（基準通貨 Cash）を支払う当事者（payer）と受け取る当事者（receiver）。
    2. priceQuantity ResolvablePriceQuantity (0..1)：quantitySchedule と priceSchedule のスコープ付き参照ポインタ（@ref:scoped）。
    3. principalPayment PrincipalPayments (0..1)：通貨スワップ等の元本交換用（FX Spot/Forward/Swap では不使用）。
    4. settlementTerms SettlementTerms (0..1)：受渡日（valueDate）や決済条件。
  • SettlementPayout 固有の4属性：
    • underlier Underlier (1..1)：必須。為替では Observable（Cash）への @ref:scoped ポインタを設定します。
    • schedule CalculationSchedule (0..1)：複数の決済期間スケジュールを定義する場合に使用します（Lesson 0008 のマルチフォワードでも活用）。
    • deliveryTerm / delivery：コモディティ先物等の限月・受渡容量用。
  • 重要な condition（制約）：
    • condition Underlier：underlier に双務契約（NonTransferableProduct）を指定することは禁止されています。
    • condition SettlementTerms：if underlier as Cash exists then settlementTerms exists — すなわち、為替取引（underlier が Cash）では settlementTerms の設定が必須です。

C2: SettlementTerms・SettlementBase・SettlementDate

SettlementTerms（product-common-settlement-type.rosetta:L287-L303）は SettlementBase（L365-L389）を継承し、決済日と決済方式を定義します。

  • 受渡日（settlementDate -> valueDate）：
    SettlementDate（L249-L269）には optional choice adjustableOrRelativeDate, valueDate, adjustableDates, businessDateRange の排他制約があります。為替の物理受渡（Spot / Forward / Swap）では、2通貨共通の受渡日として valueDate（date 型）を設定するのが標準です。
  • settlementType と transferSettlementType：
    SettlementBase には settlementType SettlementTypeEnum (1..1)（Physical / Cash / Election / CashOrPhysical）と、同時決済方式を表す transferSettlementType TransferSettlementEnum (0..1)（為替のPvP決済を表す PaymentVersusPayment 等：product-common-settlement-enum.rosetta:L45-L50）が定義されています。
    ※なお、FpML変換関数 MapFxCashSettlementToSettlementTerms（ingest-fpml-confirmation-settlement-func.rosetta:L513-L536）では、物理受渡のFX取引（fpmlFxCashSettlement is absent）において settlementDate -> valueDate のみを出力し、cashSettlementTerms を空（absent）にします。

C3: Qualify_AssetClass_ForeignExchange と Qualify_ForeignExchange_Spot_Forward

CDMでは「商品名ラベル」を人手でハードコードするのではなく、EconomicTerms を入力とする [qualification Product] 関数（product-qualification-func.rosetta）によって製品分類（ISDA Product Taxonomy）を自動推論します。

  • Step 1: 為替アセットクラス判定（Qualify_AssetClass_ForeignExchange：L143-L177）：
    SettlementPayoutOnlyExists(economicTerms -> payout)（他のPayout型が混在せず SettlementPayout のみ）であり、かつすべての SettlementPayout -> underlier が Cash（または為替インデックス）である場合に True となります。
  • Step 2: Spot / Forward 判定（Qualify_ForeignExchange_Spot_Forward：L1639-L1655）：
    ① Qualify_AssetClass_ForeignExchange(economicTerms) = True
    ② economicTerms -> payout only-element as SettlementPayout exists（SettlementPayout がちょうど1個だけ存在）
    ③ economicTerms -> payout as SettlementPayout -> settlementTerms -> cashSettlementTerms is absent（NDF用の差金決済条件が存在しない）
    ★なぜ Spot と Forward が同じ関数なのか？：製品判定関数のルート（isProduct root EconomicTerms;：L13）は EconomicTerms のみを受け取ります。約定日（tradeDate）は Trade 側にあり、また「T+2がスポットかT+1がスポットか」は通貨ペアや現地市場慣行に依存するため、EconomicTerms 単独では Spot と Forward を区別せず ForeignExchange_Spot_Forward として一括判定する設計になっています。

C4: Qualify_ForeignExchange_Swap と FpML FxSwap マッピング関数

FX Swap の製品判定関数 Qualify_ForeignExchange_Swap（product-qualification-func.rosetta:L1656-L1667）は、以下の4条件すべてが満たされたときに True を返します。

  1. Qualify_AssetClass_ForeignExchange(economicTerms) = True（全レッグの underlier が Cash）
  2. SettlementPayoutOnlyExists(economicTerms -> payout)（SettlementPayout 以外の Payout 型が含まれない）
  3. economicTerms -> payout as SettlementPayout count = 2（SettlementPayout がちょうど2個存在する）
  4. economicTerms -> payout as SettlementPayout -> settlementTerms -> cashSettlementTerms is absent（両レッグとも cashSettlementTerms が存在しない＝物理受渡）

また、FpML の fxSwap を CDM へ変換する ingest-fpml-confirmation-product-fxswap-func.rosetta（L58-L107）では、単一レッグ用の関数 MapFxCoreDetailsModelToSettlementPayout と MapFxCoreDetailsModelPriceQuantity を nearLeg と farLeg に対して2回呼び出すことで、2つの SettlementPayout と2つの PriceQuantity を生成しています。

product-qualification-func.rosetta (L1656-L1667) & ingest-fpml-confirmation-product-fxswap-func.rosetta (L58-L107) 
func Qualify_ForeignExchange_Swap:
    [qualification Product]
    inputs:
        economicTerms EconomicTerms (1..1)
    output:
        is_product boolean (1..1)
    set is_product:
        Qualify_AssetClass_ForeignExchange(economicTerms) = True
            and SettlementPayoutOnlyExists(economicTerms -> payout)
            and economicTerms -> payout as SettlementPayout count = 2
            and economicTerms -> payout as SettlementPayout -> settlementTerms -> cashSettlementTerms is absent

実務のFX取引データをマッピングする際によく登場する2つの応用パターンを押さえておきましょう。

  • パターン①：FX Swap の Near Leg / Far Leg に別々の USI / UTI がある場合（fx-ex26-fxswap-multiple-USIs.json）：
    Trade -> tradeIdentifier は TradeIdentifier (1..*) の配列であるため、identifierType: "UniqueTransactionIdentifier" を持つ要素を2つ（Near用・Far用）と、各当事者の社内取引ID（issuerReference 付き）を同一の配列内に格納します。

4. 一次ソース検証で見つかる docs/product-model.md の重大な乖離

為替の決済条件と商品スコープに関しても、二次資料 common-domain-model/docs/product-model.md には現行の .rosetta 一次ソースと完全に食い違う古い記述が残っています。マッピング設計・レビュー時には以下の2点に必ず注意してください。

⚠️ ※ドキュメントとの差分・注意点①：PriceQuantity には settlementTerms も buyerSeller も存在しない

二次資料 docs/product-model.md（L812-L814、L1058-L1127）には、「FXスポットやフォワード取引では、PriceQuantity オブジェクトが settlementTerms と buyerSeller 属性を持ち、buyer が quantity を受け取って price を支払う」と記述されています。
しかし、これは旧バージョンの廃止された設計です。現行の一次ソース observable-asset-type.rosetta:L97-L122 の PriceQuantity には price・quantity・observable・effectiveDate の4属性しかなく、settlementTerms や buyerSeller は存在しません。
現行CDMでは、決済条件（settlementTerms）と支払・受取方向（payerReceiver：PayerReceiver 型であり BuyerSeller ではない）はすべて Product -> economicTerms -> payout -> SettlementPayout（PayoutBase 継承）の側に配置されます。

⚠️ ※ドキュメントとの差分・注意点②：docs/product-model.md の Product Scope における FX Spot / Forward / Swap / NDF の記載漏れ

同じく docs/product-model.md（L328-L351「Product Scope」）のサポート対象商品リストには、為替系として 「Options: Any other OTC Options (incl. FX Options)」 しか記載されておらず、FX Spot・FX Forward・FX Swap・NDF・NDS が抜けています。
しかし一次ソース product-template-type.rosetta:L296, L406 には 「Both FX Spot and FX Forward should use this component (SettlementPayout).」 と明記されており、product-qualification-func.rosetta:L1639-L1694 には Qualify_ForeignExchange_Spot_Forward、Qualify_ForeignExchange_Swap、Qualify_ForeignExchange_NDF、Qualify_ForeignExchange_NDS が完備されています。
