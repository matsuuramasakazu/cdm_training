Phase 2 · Lesson 0003 · PriceQuantity, Observable & Scoped Metadata

為替の2通貨数量とレートを結ぶ PriceQuantity・Observable・メタデータ参照（@key:scoped / @ref:scoped）

為替取引は「通貨A（例：10,000,000 EUR）と通貨B（例：9,175,000 USD）を、合意した為替レート（例：0.9175 USD/EUR）で交換する」取引です。しかしCDMの PriceQuantity 型には quantity 属性が単数（0..1）しかありません。では2つ目の通貨金額はどこに入り、Product 内のペイアウトとどう結びつくのか？一次ソースの定義と整合性検証関数（Triangulation）から完全解明します。

🎯 このレッスンの到達ゴール（Missionへの接続）

FX Spot / Forward / Swap / NDF / FX Option のすべての商品で共通に使われる PriceQuantity（2通貨の金額・為替レートの単位方向・スポット＋フォワードポイント複合価格・対象通貨 Cash） と、それを Payout 側へ接続する @key:scoped ↔ @ref:scoped（[metadata location] ↔ [metadata address]） を迷わず設計・検証できるようになります。

1. なぜ Payout の中に具体的な金額やレートを直接書かないのか？

Lesson 0002 で「Product の中に具体的な銀行名（LEI）を書かず、外側の Trade -> party に分離する」ことを学びました。CDMは数量・価格・対象通貨についてもまったく同じ分離原則（Product-Lot Separation）を適用しています。

具体的には、契約の計算ルールを表す Product（SettlementPayout や OptionPayout）の内部には「どこにある数量・価格・対象資産を使うか」というポインタ（@ref:scoped）だけを置き、実際の金額や為替レートは外側の TradeLot -> priceQuantity（@key:scoped）に格納します。

この分離により、たとえば「1,000万ユーロのFXフォワードを途中で600万ユーロに一部解約（Partial Termination / QuantityChange）する」といったライフサイクルイベントでも、Product 内の契約条件には一切触れず、TradeLot -> priceQuantity 内の数値だけを更新すればよいアーキテクチャになっています。

2. 為替の2通貨とレートはどう格納されるか？（unit / perUnitOf / derivedQuantity）

為替取引のデータマッピングで最も重要なのが、「2つの通貨（EURとUSD）のうち、どちらを quantity に入れ、どちらを derivedQuantity に入れるのか？」という規則です。

一次ソースの変換関数 MapFxCoreDetailsModelQuantityWithLocation（ingest-fpml-confirmation-pricequantity-func.rosetta:L574-L605）および MapExchangeRateToPrice（L1365-L1427）を読むと、その決定ロジックが100%明確に定義されています。すべては為替レートのクオート基準（QuoteBasisEnum）から決まります。

為替クオート基準と PriceQuantity の対応関係（fx-ex03-fx-fwd.json: 1 EUR = 0.9175 USD の例） 
// 前提：1 EUR あたり 0.9175 USD（Currency2PerCurrency1: USD per EUR）で 10,000,000 EUR と 9,175,000 USD を交換
"tradeLot" : [ {
  "priceQuantity" : [ {
    "price" : [ {
      "@key:scoped" : "price-1",
      "value" : 0.9175,                      // ① アウトライト・フォワードレート (0.9130 + 0.0045)
      "unit" : { "currency" : { "@data" : "USD" } },      // ② 分子（対価通貨 / Term Currency）：USD
      "perUnitOf" : { "currency" : { "@data" : "EUR" } }, // ③ 分母（1単位あたりの基準通貨 / Base Currency）：EUR
      "priceType" : "ExchangeRate",
      "composite" : {                        // ④ スポットレートとフォワードポイントの内訳
        "baseValue" : 0.9130,                //    スポットレート (Spot Rate)
        "operand" : 0.0045,                  //    フォワードポイント (Forward Points)
        "arithmeticOperator" : "Add",
        "operandType" : "ForwardPoint"
      },
      "derivedQuantity" : {                  // ⑤ 対価通貨（unit = USD）の金額は derivedQuantity に入る！
        "value" : 9175000,
        "unit" : { "currency" : { "@data" : "USD" } }
      }
    } ],
    "quantity" : {                           // ⑥ 基準通貨（perUnitOf = EUR）の金額は quantity に入る！
      "@key:scoped" : "quantity-1",
      "value" : 10000000,
      "unit" : { "currency" : { "@data" : "EUR" } }
    },
    "observable" : {                         // ⑦ 対象資産（observable）も基準通貨（perUnitOf = EUR）の Cash！
      "@key:scoped" : "observable-1",
      "@data" : {
        "@type" : "cdm.base.staticdata.asset.common.Cash",
        "identifier" : [ {
          "identifier" : { "@data" : "EUR" },
          "identifierType" : "CurrencyCode"
        } ],
        "assetType" : "Cash"
      }
    }
  } ]
} ]

鉄則：分母（perUnitOf）と分子（unit）による役割分担

  • 分母の通貨（perUnitOf ＝「1単位あたり」の基準通貨：上記では EUR）：
    主数量である PriceQuantity -> quantity（10,000,000 EUR）および PriceQuantity -> observable（Cash: EUR）になります。そして SettlementPayout -> payerReceiver の payer は、この perUnitOf 通貨（observable）を支払う当事者を指します。
  • 分子の通貨（price -> unit ＝ レート表記の対価通貨：上記では USD）：
    PriceSchedule -> derivedQuantity（算出数量：9,175,000 USD）になります。一次ソースの condition DerivedQuantityUnit（observable-asset-type.rosetta:L196-L198）により、derivedQuantity -> unit は必ず親の price -> unit と同じ通貨でなければならないことが強制されています。
  • 三角整合性チェック（condition PriceQuantityTriangulation）：
    PriceQuantity 型の制約 PriceQuantityTriangulation(price, quantity) = True（observable-asset-type.rosetta:L120-L121, observable-common-func.rosetta:L18-L38）により、CDMは自動的に以下の等式を検証します： \[ \underbrace{\text{price.value}}_{0.9175\text{ (USD/EUR)}} \times \underbrace{\text{quantity.value}}_{10,000,000\text{ (EUR)}} = \underbrace{\text{price.derivedQuantity.value}}_{9,175,000\text{ (USD)}} \]

C1: PriceQuantity と三角整合性（PriceQuantityTriangulation）

PriceQuantity は TradeLot -> priceQuantity (1..*) の要素であり、1つのレッグの価格・数量・対象物を束ねます。

  • price PriceSchedule (0..*)：[metadata location] 付き。為替レートやオプションの算出数量を保持。
  • quantity NonNegativeQuantitySchedule (0..1)：[metadata location] 付き。単数（0..1）であり、基準通貨（perUnitOf）の金額を保持。
  • observable Observable (0..1)：[metadata location] 付き。対象通貨（Cash）またはインデックスを保持。
  • effectiveDate AdjustableOrRelativeDate (0..1)：途中増額・減額ロットの発効日（通常の新規約定では省略）。
  • condition PriceQuantityTriangulation：priceType が ExchangeRate（または AssetPrice）であり、price -> value、quantity -> value、derivedQuantity -> value の3つが存在する場合、value * noOfUnits = derivedQuantity -> value が成立しないとバリデーションエラーになります。
observable-asset-type.rosetta (L97-L122) & observable-common-func.rosetta (L18-L38) 
type PriceQuantity:
    [metadata key]
    price PriceSchedule (0..*)
        [metadata location]
    quantity NonNegativeQuantitySchedule (0..1)
        [metadata location]
    observable Observable (0..1)
        [metadata location]
    effectiveDate AdjustableOrRelativeDate (0..1)

    condition PriceQuantityTriangulation: <"Check price quantity triangulation.">
        PriceQuantityTriangulation(price, quantity) = True

func PriceQuantityTriangulation:
    inputs:
        price PriceSchedule (0..*)
        quantity NonNegativeQuantitySchedule (0..1)
    output:
        success boolean (1..1)
    alias noOfUnits:
        quantity extract if multiplier exists then value * multiplier -> value else value
    set success:
        price
            filter priceType = AssetPrice or priceType = ExchangeRate
            then extract
                if value exists and noOfUnits exists and derivedQuantity -> value exists
                then value * noOfUnits = derivedQuantity -> value
            then if any = False then False else True

C2: PriceSchedule と derivedQuantity の厳密な制約

PriceSchedule（observable-asset-type.rosetta:L135-L203）は MeasureBase を継承し、価格を「1単位の perUnitOf あたり、いくらの unit か」という比率として表現します。

  • priceType PriceTypeEnum (1..1)：必須。為替レートでは必ず ExchangeRate を指定します。
  • condition UnitOfAmountExists：Variance / Volatility / Correlation 以外のすべての価格型では、unit と perUnitOf の両方が必須（exists）です。
  • condition PositiveAssetPrice：ExchangeRate の value は必ず正の数（> 0）でなければなりません。
  • condition DerivedQuantityUnit：derivedQuantity と unit が共に存在する場合、derivedQuantity -> unit = unit（通貨の一致）が強制されます。
common-domain-model/rosetta-source/src/main/rosetta/observable-asset-type.rosetta (L135-L203) 
type PriceSchedule extends MeasureBase:
    perUnitOf UnitType (0..1)
    priceType PriceTypeEnum (1..1)
    priceSubType PriceSubTypeEnum (0..1)
    priceExpression PriceExpressionEnum (0..1)
    composite PriceComposite (0..1)
    arithmeticOperator ArithmeticOperationEnum (0..1)
    premiumType PremiumTypeEnum (0..1)
    derivedQuantity NonNegativeQuantitySchedule (0..1)

    condition UnitOfAmountExists:
        if priceType = Variance or priceType = Volatility or priceType = Correlation
        then unit is absent and perUnitOf is absent
        else unit exists and perUnitOf exists

    condition PositiveAssetPrice:
        if (priceType = ExchangeRate or priceType = AssetPrice)
                and arithmeticOperator is absent
        then value > 0 or datedValue -> value all > 0

    condition DerivedQuantityUnit:
        if derivedQuantity exists and unit exists
        then derivedQuantity -> unit = unit

C3: PriceComposite（スポットレート ＋ フォワードポイントの合成）

FXフォワードやNDF、FXスワップでは、約定したフォワードレート（例：0.9175）だけでなく、その内訳であるスポットレート（Spot Rate：0.9130）とフォワードポイント（Forward Points / 直先スプレッド：0.0045）を契約確認書（Confirmation）に記載することが一般的です。

  • baseValue number (1..1)：アンカーとなるスポットレート。condition PositiveSpotRate により > 0 が必須。
  • operand number (1..1)：加減算するフォワードポイント（スワップポイント）。
  • arithmeticOperator ArithmeticOperationEnum (1..1)：operandType = ForwardPoint の場合、condition ArithmeticOperator により Add または Subtract のみが許可されます。
  • operandType PriceOperandEnum (0..1)：ForwardPoint を指定します。condition ForwardPoint（observable-asset-type.rosetta:L181-L183）により、operandType = ForwardPoint のときは priceType = ExchangeRate が必須となります。
observable-asset-type.rosetta (L123-L134, L156-L160, L181-L183) 
type PriceComposite:
    baseValue number (1..1) <"e.g. the clean price (Bond) or the spot rate (FX).">
    operand number (1..1) <"The 2nd operand...">
    arithmeticOperator ArithmeticOperationEnum (1..1)
    operandType PriceOperandEnum (0..1) <"e.g. accrued or forward point.">

    condition ArithmeticOperator:
        if operandType = PriceOperandEnum -> ForwardPoint
                or operandType = PriceOperandEnum -> AccruedInterest
        then arithmeticOperator = ArithmeticOperationEnum -> Add
                or arithmeticOperator = ArithmeticOperationEnum -> Subtract

// PriceSchedule 側の関連制約
condition PositiveSpotRate:
    if (priceType = ExchangeRate or priceType = AssetPrice) and composite -> baseValue exists
    then composite -> baseValue > 0

condition ForwardPoint:
    if composite -> operandType = ForwardPoint
    then priceType = ExchangeRate

C4: NonNegativeQuantitySchedule と Cash（通貨資産）

PriceQuantity -> quantity と observable は、どちらも為替レートの分母（perUnitOf）の通貨を表します。

  • NonNegativeQuantitySchedule（base-math-type.rosetta:L33-L56）：
    親の QuantitySchedule で override unit UnitType (1..1) が指定されているため、unit（通貨 currency 等）は常に必須です。単一金額の場合は value に正の数値（NonNegativeNumber）を入れ、ステップアップ／アモチゼーション等で期間ごとに金額が変わる場合は datedValue を使います。
  • Observable -> Asset -> Cash（base-staticdata-asset-common-type.rosetta:L102-L119）：
    為替取引で受け渡す（または参照する）対象資産は「現金通貨（Cash）」です。Cash 型の4つの condition により、① identifierType = CurrencyCode の識別子がちょうど1つ存在し有効な通貨コードであること、② taxonomy is absent、③ isExchangeListed is absent、④ assetType = Cash が厳密に強制されます。

C5: ResolvablePriceQuantity と @key:scoped ↔ @ref:scoped

SettlementPayout や OptionPayout が継承する PayoutBase は、priceQuantity ResolvablePriceQuantity (0..1) と underlier Underlier (1..1) を持ちます。

  • [metadata address "pointsTo"=PriceQuantity->...] の仕組み：
    .rosetta 定義で [metadata address "pointsTo"=PriceQuantity->quantity] と宣言された属性（ResolvablePriceQuantity -> quantitySchedule）は、JSONシリアライズ時に値を持たず {"@ref:scoped": "quantity-1"} というスコープ付きポインタになります。
  • 複数レッグ（FX Swap）でのスコープ分離：
    FX Swap（fx-ex08-fx-swap.json）のように2つの SettlementPayout と2つの PriceQuantity がある場合、Near Leg は quantity-1 / price-1 / observable-1 を指し、Far Leg は quantity-2 / price-2 / observable-2 を指すことで、どのペイアウトがどのロット価格・数量に対応するかを一意に解決します（次回の Lesson 0004 で詳解）。

4. 一次ソース検証で見つかる docs/product-model.md の重大な乖離

PriceQuantity はCDMのバージョンアップで大きなスキーマ変更が行われた領域であり、二次資料 common-domain-model/docs/product-model.md には現行の .rosetta スキーマと矛盾する古い説明が2箇所残っています。設計レビュー時は必ず以下の一次ソース仕様を正としてください。

⚠️ ※ドキュメントとの差分・注意点①：PriceQuantity -> quantity は配列ではなく単数（0..1）

二次資料 docs/product-model.md（L853-L862、L1021）には、「price と quantity はどちらも PriceQuantity 内で配列（array）として複数指定でき、2つの数量表現を並べて格納できる」と記述されており、JSON例でも "quantity": [ { ... } ] と配列で書かれています。
しかし、現行の一次ソース observable-asset-type.rosetta:L101 では quantity NonNegativeQuantitySchedule (0..1) と単数（スカラー）に変更されています。為替取引の2つ目の通貨金額を quantity 配列の2要素目に入れようとするとスキーマ違反になるため、必ず price -> derivedQuantity (0..1)（observable-asset-type.rosetta:L144）に格納してください。

⚠️ ※ドキュメントとの差分・注意点②：スポットレートとフォワードポイントは別々の price 要素ではない

同じく docs/product-model.md（L858-L860）には、「FXフォワード取引では、スポットレート、フォワードポイント、フォワードレートの3つをそれぞれ price 配列の要素として指定できる」と書かれています。
しかし、現行の一次ソース変換関数 MapExchangeRateToPrice（ingest-fpml-confirmation-pricequantity-func.rosetta:L1395-L1427）および公式検証済みJSON（fx-ex03-fx-fwd.json）では、price 配列の要素は1つだけであり、その value にフォワードレート、内側の composite（PriceComposite）に baseValue（スポットレート）と operand（フォワードポイント）を格納するのが正規パターンです。
