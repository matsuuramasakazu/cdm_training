2. カーディナリティ（多重度：必須／任意／リスト）の読み方

.rosetta のすべての属性定義は 属性名 型名 (最小数..最大数) <"説明"> の形式で書かれます。マッピング設計で「NULL許容か」「配列か」「固定長か」を判断する最重要指標です。

表記 マッピング上の意味 実務での注意点と一次ソース例
(1..1) 必須・単一値（Required Scalar） 省略不可。例：Trade -> tradeDate date (1..1)（約定日は必ず1つ存在する）。
(0..1) 任意・単一値（Optional Scalar） 省略可能だが、特定の商品では後述の condition によって必須化または禁止されることが多い。
(0..*) 任意・複数リスト（0個以上の配列） 例：TradeState -> resetHistory Reset (0..*)（Fixing履歴は0件以上）。
(1..*) 必須・複数リスト（1個以上の配列） 最低1要素が必須の配列。例：EconomicTerms -> payout Payout (1..*)（FX Forwardは1要素、FX Swapは2要素、シンセティック・マルチフォワードは複数要素）。
(2..2) 要素数2個固定のリスト 例：TradableProduct -> counterparty Counterparty (2..2)（取引当事者は必ず Party1 と Party2 の2者ちょうど）。

3. 制約条件（condition）とパス演算子の読み方

CDMでは、属性のカーディナリティ自体は (0..1) と緩めに定義しておき、商品の種類や状態に応じた厳密なルールを型末尾の condition ブロックで強制します。

構文・演算子 意味 一次ソースでの実例
A -> B -> C 階層ナビゲーション（Aの中のBの中のC） settlementTerms -> cashSettlementTerms
A ->> B choice型を跨ぐナビゲーション underlier as Product ->> economicTerms
X as SomeType choice型の型絞り込み（キャスト） economicTerms -> payout as SettlementPayout（Payout選択型のうち SettlementPayout である要素を取り出す）
exists / is absent 値が存在する ／ 存在しない（空） FX Spot/Forward では cashSettlementTerms is absent（物理受渡）、NDFでは cashSettlementTerms exists（差金決済）。
only-element / count = N 要素が1つだけ ／ 要素数がN個 FX Spot/Forward は payout only-element as SettlementPayout exists（1個のみ）、FX Swap は count = 2（Near/Farの2個）。
required choice A, B
one-of		 AとBのうち必ずどちらか1つだけが存在する OptionStrike の one-of：通常の strikePrice と平均ストライク averagingStrikeFeature は同時に指定できない。

4. メタデータ参照（[metadata ...] と JSON の @key / @ref）

CDMのJSONデータを初めて読む人が最もつまずきやすいのが、同じデータを2回書かずにID参照で結ぶ仕組みです。

.rosetta 定義上の記述 JSON 実データ上の表記 仕組みと為替データでの役割
[metadata key]（定義側）
[metadata reference]（参照側） 		定義側："@key:external": "party1"
参照側："@ref:external": "party1" 		外部／オブジェクト間参照。
取引当事者の実体（LEI等の Party）は Trade -> party に1度だけ定義し、counterparty 等からは @ref:external で参照する。
[metadata address "pointsTo"=PriceQuantity->quantity] 実体側（TradeLot内）：
"@key:scoped": "quantity-1"
参照側（Payout内）：
"@ref:scoped": "quantity-1" 		スコープ付きアドレス参照（ProductとTradeLotの分離）。
Product（商品の契約テンプレート）内の SettlementPayout や OptionPayout には具体的な金額・レートを直接書かず、"@ref:scoped": "quantity-1" というポインタを置き、実際の金額（10,000,000 EURなど）は TradeLot -> priceQuantity 側の "@key:scoped": "quantity-1" に格納する。
